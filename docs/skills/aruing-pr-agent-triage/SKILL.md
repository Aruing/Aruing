# PR-Agent 评审分诊

## 作用范围

处理 CI 里 pr-agent（外部 LLM 评审）对 PR 提出的发现：核实每条是否成立，成立则**按类修复**（同一根因、同一边界族一次修完），不成立则实测证伪并钉板。目标只有一个：**用最少的修改轮次让评审收敛**——每次 push 触发一轮全新评审，轮次是时间成本。

不替代 pr-agent（外部评审）、不替代 `aruing-pr-description`（开 PR 与 PR 前自检）；不替维护者裁决合并。

## 核心原则

1. **先实测，再改动**：每条发现先写验证测试复现（或证伪），裁决三选一——采纳 / 证伪 / 钉板设计语义。不做无证据的反射性改码
2. **修类不修点**：被采纳的发现，先归族（输入面校验缺失 / 数值退化 / 语义域越界 / 并发 / 资源泄漏…），再对 PR 改动范围做同族全扫，一族一个 commit 修完。修实例不修类 = 下一轮兄弟洞排队出现
3. **批量单推**：一轮的全部发现（含同族扫描结果、证伪钉板）合并为一个 commit 推送一次；绝不逐条推送
4. **轮次记账**：向维护者汇报「第 N 轮：X 采纳 / Y 证伪」，让收敛趋势可见；连续两轮全部证伪（纯数值玄学、无复现路径）时，建议维护者按停止规则合并

## 流程

### 1. 取评论（git/API 为准，不靠猜）

```bash
gh api repos/<owner>/<repo>/issues/<N>/comments --jq '.[] | select(.user.login == "github-actions[bot]") | .body'
```

- pr-agent 的 persistent review **原地更新同一条评论**：以 `Review updated until commit <sha>` 确认它评审的是哪个 commit；sha 与上次处理一致 = 无新发现
- 区分新发现与已处理项：逐条对照上次处理记录（会话内记忆 / PR 描述 / 本地笔记）；只处理新增
- 注意 pr_agent job 是否已跑完（`gh pr checks`）：job pending 时评论还是旧一轮

### 2. 逐条实测裁决

对每条发现：

| 步骤 | 动作 |
| --- | --- |
| 读声称路径 | 在代码里走一遍它声称的调用链，标出哪一步实际不成立（如溢出被 log-sum-exp 稳定性挡住） |
| 写验证测试 | 复现（采纳）或证伪（跑出与声称相反的结果）临时跑，裁决后保留为回归测试 |
| 裁决 | **采纳**：路径成立且产生错误行为（含静默语义污染——某分支恒真/恒假）／**证伪**：路径不存在或行为即设计语义／**钉板**：行为正确但值得用测试固定语义 |

- 静默语义污染最危险：值不崩、不 NaN，但让某条出口/开关恒真恒假（如 `Tau=Inf` 恒报平台）——看比较与分支，不只看算术
- 「发现路径错但指向的区域有真缺陷」是常见模式：即使证伪核心声称，也把周边实测一遍

### 3. 采纳项按类修复

1. 归族：这条属于哪个输入面/哪类退化（参考 `aruing-pr-description` §PR 前对抗自检的族清单）
2. 同族全扫：PR 改动的全部代码里这一族还住在哪（同一结构体的兄弟字段、同一函数的兄弟参数、同一模式的其他出现点）
3. 一族一个 commit：修复 + 族名写进 commit message（例：「输入面校验缺失族：矩阵对齐 + 成本域 + 结果名唯一」）
4. 回归测试钉住族内每个成员

### 4. 单次批量推送 + 汇报

- 全部采纳修复 + 证伪钉板 + 文档注记 → 一个 commit → push 一次
- 汇报格式：

```text
第 N 轮裁决：
| 发现 | 裁决 | 依据 |
采纳 X：修了什么 + 扫出的同族成员
证伪 Y：实测证据（路径断在哪 / 设计语义是什么）
钉板 Z：钉进哪个测试
下一轮预期：……（若连续两轮全证伪 → 建议按停止规则合并）
```

## 历史教训（#119 五轮复盘，规则来源）

- 消费点逐条打补丁挡不住导出类型绕过构造器的兄弟洞——封闭不变量 + 构造器集中校验才是族的修法
- `x <= 0` 判断对 NaN 为 false、+Inf 穿透——数值防护统一用 `!(v > 0) || IsInf(v, 0)` + 语义域（概率 ≤1、阈值方向）
- 参数面与数据输入面同权：自检清单漏了哪个面，评审就会从那个面来
- exp 溢出/连乘溢出的比较一律走对数域
